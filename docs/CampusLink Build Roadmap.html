CampusLink build roadmap

One backend, one database, three dashboards. Every dashboard is a filtered view of the same records, and a status field moves work from one person to the next.

StudentRegisters, uploads resume, sees eligible drives, opts in, tracks status and offers.
RecruiterPosts a job, sees ranked students, picks the top 50, releases offers.
Placement cell (admin)Loads official records, approves at three gates, schedules drives, watches analytics.

4. The three engines

Eligibility engine (rules only)

Checks master CGPA, branch and backlogs against the drive rules. Returns yes or no with a reason. Always uses master data, never what the student typed.

Verification engine

Compares resume text and student entries with the master record.

CheckResult
Resume CGPA or backlogs differ from masterRed flag: admin must review
Skill listed but absent from resume or projectsYellow flag: lower weight
Certificate without proof file or linkYellow flag: marked unverified
Everything matchesClean: can be approved in bulk

Ranking engine

Fit score out of 100. Tune the weights later.

PartWeight
Skill match with the JD40
Relevant projects and certifications20
Mock interview and aptitude25
CGPA (from master record)15

Levels: Not Ready, Developing, Ready, Highly Employable. Each student gets a written reason based on recorded skills, projects, assessments, and academic data.

7. Build order

Phase 1: Foundation

  • FastAPI project, MongoDB, login with roles
  • Collections above, roster uploaded from authorized college records
  • Role check and status-transition helper
Done when: three roles can log in and see an empty dashboard.

Phase 2: Student profile

  • Register with registration number, auto-fill and lock academic fields
  • Resume upload, skill extraction, readiness score, skill gaps
Done when: a student sees a readiness level and missing skills.

Phase 3: Drive workflow

  • Recruiter posts job, admin approves (Gate 1)
  • Eligibility check, Apply button on or off with reason
  • Opt-in creates the application
Done when: a job travels from recruiter to admin to a student's dashboard.

Phase 4: Verification and ranking

  • Compare resume with master record, red and yellow flags
  • Admin verification screen (Gate 2)
  • Weighted fit score with written reasons
Done when: a wrong CGPA gets flagged and verified students appear ranked for the recruiter.

Phase 5: Selection and scheduling

  • Recruiter picks top 50, admin approves (Gate 3)
  • Conflict check: same date and slot, same venue, same student in two drives
  • Notifications when students are shortlisted
Done when: students see "Shortlisted" and double-booking is blocked.

Phase 6: Offers, analytics, polish

  • Offer and document tracker (accept, defer, withdraw)
  • Dashboard: registered and ready students, drives, offers, branch-wise rate, packages
  • At-risk students calculated from current readiness metrics
  • Student chatbot for eligibility questions (optional)
Done when: the full placement workflow runs against uploaded records.

8. End-to-end test sequence

Use authorized college roster data and real test accounts. Upload the roster, post recruiter jobs with actual requirements, log in with individual student registration numbers, upload each student's resume, and verify eligibility, applications, review gates, ranking, shortlists, offers, and analytics against the records entered.
